연금로드 다이어그램

구현 기준 2026-09-06(main). 각 다이어그램은 확대·검색·경로 추적이 되는 단독 HTML입니다. 뷰어의 버튼 문구(Light, Present, Export 등)는 영어입니다.

  1. 시스템 구성architecture

    서버 없는 정적 SPA. UI 계층(app.ts · 렌더 모듈 · 연출 실행), 순수 함수 엔진(game · tile-effects · market · portfolio · scoring), 콘텐츠 JSON, LocalStorage, Vercel 배포와 검증(Vitest · 시뮬)이 어떻게 이어지는지.

  2. 한 턴의 순서workflow

    주사위 → startTurn(시장 반영 · 주문 체결 · 칸 효과) → 속보 카드(IRP 반영 · 도착 효과) → (칸 설명 · 생활사건) → 운용 시트(운용지시 칸은 2회) → performAction → 게이트(성향 · 70%) → finalizeTurn → 정산 장면(막대 3개 · 고스트) → 다음 턴 또는 결과.

  3. 데이터 흐름 — 시드에서 결과까지dataflow

    시드 하나가 국면 엔진 · 충격/신호 · 생활사건 일정 · 고스트 경로를 만들고, 턴마다 수익률이 먼저 보유분에 반영된 뒤 칸 효과 · 사건 · 플레이어 행동이 GameState에 이어져 월 연금 · 별 · 기록이 되는 길.

  4. 상태 흐름lifecycle

    타이틀 → 주사위 → 속보(시장은 이미 반영) → 운용 1~2회 → 정산 장면의 레일을 12번 돌고, 거절 · 보류는 운용으로 되돌아가며, 12턴째 마감만 결과 리포트로 내려간다.

  5. 한 턴의 호출 순서 — 시장 먼저sequence

    startTurn이 applyMarketStep → settleOrders → applyTileArrival로 시장을 먼저 반영한 뒤, performAction 한 호출 안에서 buyProduct → policy 게이트 → finalizeTurn → summarizeTurn이 차례로 끝나는 순서.
