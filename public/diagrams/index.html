연금로드 다이어그램

구현 기준 2026-09-06 묶음 C(prod-2026-09-06-bundle-c). 각 다이어그램은 확대·검색·경로 추적이 되는 단독 HTML입니다. 뷰어의 버튼 문구(Light, Present, Export 등)는 영어입니다.

  1. 시스템 구성architecture

    서버 없는 정적 SPA. UI 계층(app.ts · 렌더 모듈 · 연출 실행), 순수 함수 엔진(game · life · quiz · market · portfolio · default-option · scoring · milestones · achievements), 콘텐츠 JSON(default-options 포함), LocalStorage v6(설정 · 기록 · 업적 · 컬렉션), Vercel 배포와 검증(Vitest 359 · 시뮬 11전략)이 어떻게 이어지는지.

  2. 한 턴의 순서workflow

    주사위 → startTurn(시장 반영 · 주문 체결 · 칸 효과) → 속보 카드(IRP 반영 · 도착 효과) → (칸 설명 · 퀴즈 1문항 · 생활사건 3지선다) → 운용 시트(운용지시 칸은 2회, 「그대로」는 확인 없이 디폴트옵션 매수·마감) → performAction → 게이트(성향 · 70%) → finalizeTurn → 정산 장면(막대 3개 · 이정표 · 고스트, 상품별·내가 한 일은 「자세히」 접힘, 평범한 턴은 자동 진행 옵션) → 다음 턴, 12턴이면 퀴즈 ≤3 → 수령 방식 → 결과(새 업적 · 결과 복사).

  3. 데이터 흐름 — 시드에서 결과까지dataflow

    시드 하나가 국면 엔진 · 충격/신호 · 생활사건(12종 3지선다) · 퀴즈 출제 · 고스트 경로를 만들고, 턴마다 수익률이 먼저 보유분에 반영된 뒤 칸 효과 · 사건 · 플레이어 행동(디폴트옵션 포함)이 GameState에 이어져 수령 계수 → 월 연금 · 별 · 서사 · 업적 → 저장 v6(기록 · 업적 · 컬렉션)가 되는 길.

  4. 상태 흐름lifecycle

    타이틀(주간 시드 · 디폴트옵션 지정) → 주사위 → 속보 · 퀴즈 · 사건(시장은 이미 반영) → 운용 1~2회 → 정산 장면의 레일을 12번 돌고, 거절 · 보류는 운용으로 되돌아가며, 12턴째 마감은 마무리(퀴즈 ≤3 · 수령 방식)를 거쳐 결과 리포트(별 · 서사 · 새 업적)로 내려간다. 정산 장면은 접기와 자동 진행 옵션이 있다.

  5. 한 턴의 호출 순서 — 시장 먼저sequence

    startTurn이 applyMarketStep → settleOrders → applyTileArrival로 시장을 먼저 반영한 뒤, performAction 한 호출 안에서 buyProduct → policy 게이트(「그대로」면 applyDefaultOption) → finalizeTurn → stampMilestones → summarizeTurn이 차례로 끝나는 순서.
